The urn:solid namespace

Draft specification — for review by the W3C Solid Community Group.

Summary

The urn:solid namespace provides location-independent identifiers for use in Solid-based applications where stable naming across protocols, storage locations, or offline contexts is required. It complements HTTP URIs rather than replacing them: HTTP remains the primary mechanism for dereferencing resources on the Web.

Scope

Identifiers in this namespace fall into two broad categories.

Vocabulary terms — stable names for classes and properties that map to existing RDF predicates (e.g. urn:solid:Person → foaf:Person), giving agents and LLMs a single, predictable surface that survives vocabulary churn and registry drift.

Logical resources, agents, and application-level objects whose identity should persist independently of any particular origin or transport.

Resolution

Resolution, where needed, is handled by application-level mechanisms — typically a mapping to an HTTP URI, a WebID, or another concrete identifier. The namespace itself does not prescribe a single resolution protocol; an identifier may resolve differently in different deployments without changing identity.

Use cases

  • Signed data — content whose identity must outlive its current hosting URL.
  • Cross-protocol references — identifiers cited from non-HTTP transports (Nostr, Matrix, IPFS, local filesystems).
  • Agent-to-agent messaging — stable subject lines for messages that may be relayed or stored without an authoritative origin.
  • Local-first systems — applications that operate offline or with intermittent connectivity, where binding identity directly to a URL is insufficient or undesirable.
  • Vocabulary indirection — a single name (urn:solid:Person) that an agent can rely on even as upstream registries reorganise or deprecate terms.

Relationship to HTTP URIs

urn:solid is not a replacement for HTTP URIs. Where a resource has a stable HTTP identity and dereferencing is the primary need, an HTTP URI remains the right choice. urn:solid is intended for the cases where it is not — and to give vocabulary terms one canonical name across the multiple HTTP URIs that, today, identify them in different upstream registries.

Status

This is an early draft. The companion registry at urn-solid.github.io is the operational implementation of the vocabulary-term portion of the namespace. Comments and proposals are welcome via the issue tracker.
